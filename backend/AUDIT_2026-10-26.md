# NEBULA audit — 26 October 2026

## Scope and evidence
Inspected the connected NEBULA account, seven existing Workers, their bindings and schedules, three D1 schemas, production API source, evaluation source, scanner/AI source, auth staging source, repository modules and frontend. Production index.html matched GitHub byte-for-byte before changes; its inline script passed node --check. No browser interaction test was performed. B-SMART was not accessed.

## Applied fixes (d7cf392)
- API: enforce authentication on bulk prediction/evaluation subroutes; reject absent server credentials; cap bulk arrays at 100; clamp negative pagination (SQLite LIMIT -1 otherwise returns unlimited rows).
- AI engine: absent or non-SAFE whale assessment remains unverified; reject null/nonobject input items.
- Scanner: preserve upstream HTTP 429, apply five-minute scheduled cooldown using persisted diagnostics, validate all result identities before writes, atomically save each snapshot/score pair, cap scoring requests at 200.
- Repository prediction policy: require explicit false for mint/freeze authorities. Corrected an invalid test assumption: lowercasing a Base58 string is not necessarily syntactically invalid.
- Checked the deployed Worker sources into backend/workers so these fixes are reviewable in GitHub.

## Unresolved — do not describe the application as fully repaired
1. The frontend embeds a shared API credential. Closing the anonymous bulk bypass does NOT prevent a visitor who copies that credential from writing. Complete session authentication integration and revoke the exposed credential together; auth is currently staged, not wired into production UI/API. Credential values must never be included in reports.
2. Scanner cron still targets one fixed test mint and writes to nebula-scanner-stage, not the production predictions database. This is a probe, not broad market discovery. The frontend is not connected to the new scanner/engine pipeline. Expanding this requires an explicit data contract and discovery strategy, rather than treating it as a one-line bug.
3. DexScreener still returns intermittent 429. Cooldown reduces repeat calls; it does not restore provider capacity or prove sustained recovery.
4. The new engine is an uncalibrated heuristic, not a trained predictive model. It has no calibrated profit probability. Do not use it for automatic trading.
5. Evaluation uses current sampled prices and a 40-minute eligibility band. It cannot reconstruct expired historical windows. Its sustained-hours calculation is heuristic, not measured OHLCV persistence. Existing evaluations were preserved.
6. Legacy pattern_stats and feature_contributions foreign keys still reference predictions_backup. A data migration requires mapping and validation; no destructive migration was attempted.
7. Frontend still performs substantial scoring/enrichment locally and contains legacy display/cache behavior. Syntax and byte equality checks are not a full UI/security audit. Authentication migration and browser regression testing remain necessary.

No trades were executed or enabled. Existing BUY fail-closed enforcement remains in the API.
